# 악필

말소리를 듣고 실시간으로 받아쓰는 회의록 앱. 프레임워크 없는 정적 PWA.
제작 · 작은앱공방

## 지금 되는 것 (최소본)

- 마이크 하나로 **녹음 + 실시간 받아쓰기**를 동시에
- 화자 칩 — 이름을 탭하면 그 시점부터 발언자가 붙는다
- 중요 · 할일 표시, 문장 직접 수정
- 종료하면 자동 저장 → 정리 화면에서 제목·참석자 입력
- 문장을 탭하면 **녹음의 그 지점으로 점프**
- 복사 / 공유 (Web Share)
- 회의 목록, 삭제
- 화면 꺼짐 방지 (Wake Lock)
- 앱이 죽어도 텍스트는 남는다 (초안 자동 보관 → 다음 실행 때 복구 제안)
- 설정 — 함께 녹음하기 끄기, 문단 나누기 간격, 화자 칩 표시, 글자 크기, **용어 사전**

### 용어 사전

회사 약어나 사람 이름처럼 늘 틀리게 들리는 말을 자동으로 고친다
(`에이사 → A사`). 체감 정확도가 여기서 제일 크게 올라간다.
긴 규칙부터 적용하므로 짧은 규칙이 먼저 먹어 망가지는 일은 없다.

## 아직 없는 것

회의 템플릿(안건/논의/결정/할일), 자동 요약.

## 파일

| 파일 | 하는 일 |
|---|---|
| `index.html` | 화면 네 개 (녹음 / 정리 / 목록 / 설정) |
| `styles.css` | 다크 + 네온 |
| `app.js` | 음성 인식, 녹음, 저장, 공유 |
| `sw.js` | 서비스워커 |
| `tools/make_icons.py` | 아이콘 재생성 (`python tools/make_icons.py`) |

## 고칠 때 반드시

에셋을 하나라도 고치면 **`sw.js` 의 `CACHE` 버전을 올린다.**
안 올리면 기기는 저장된 옛 코드를 계속 쓴다. "고쳤는데 그대로다"의 대부분이 이것.

## PC에서 돌려보기

```bash
python -m http.server 8130 --bind 127.0.0.1 --directory akpil
```

`http://localhost:8130` 으로 연다. 음성 인식은 `localhost` 또는 HTTPS 에서만 동작한다.

## 폰에서 돌려보기 (배포 전)

USB 로 연결하고 ADB 로 PC 포트를 폰에 붙인다. 안드로이드만 된다.

```bash
adb reverse tcp:8130 tcp:8130
```

폰 크롬에서 `http://localhost:8130`. 아이폰은 이 방법이 없으므로 GitHub Pages 배포 후 테스트한다.

## 실기기 확인 목록

처음 돌릴 때 이 순서로 본다. **1번이 안 되면 나머지는 볼 필요 없다.**

1. **아이폰에서 녹음과 받아쓰기가 같이 되는가** — 가장 위험한 지점.
   iOS 는 오디오 세션이 배타적이라, 녹음(`getUserMedia`)이 음성 인식을 밀어낼 수 있다.
   글이 안 올라오면 **설정 → 함께 녹음하기를 끄고** 다시 해본다.
   그때 글이 올라오면 원인이 확정된 것이다.
2. 30분 연속으로 끊기지 않는가 — iOS 는 수십 초마다 인식이 스스로 끝난다.
   자동 재시작을 넣어두었지만 실제로 버티는지 봐야 한다.
3. 화면이 안 꺼지는가 (상태 바에 "화면 유지"가 떠 있는지)
4. 회의실 거리(2~3m)에서 얼마나 알아듣는가
5. 공유가 카톡·메일로 넘어가는가

## 알아둘 것

- 음성은 **구글/애플 서버를 거쳐** 텍스트가 된다. 인터넷이 끊기면 받아쓰기가 멈춘다.
- 녹음 파일과 회의록은 **기기 안에만**(IndexedDB) 저장된다. 서버로 보내지 않는다.
  브라우저 저장소를 비우면 같이 지워진다.
- 화면이 꺼지거나 앱이 뒤로 가면 브라우저가 얼어붙는다. **회의 내내 화면을 켜두고 충전기를 꽂는다.**
